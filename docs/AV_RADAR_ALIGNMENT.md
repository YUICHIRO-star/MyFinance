# AV JAPAN radarとの設計上の接点

2026-09-18時点で確認できた別会話の構想を参照した設計メモ。Radarの実装・API・リポジトリは未確認であり、接続済みではない。

Radarは国内の自動運転案件、自治体、企業、車両、実証／商用段階、補助金、公募を構造化して検索する構想。MyFinanceとは別サービスとして扱う。以下は将来の共通化候補であり、現時点で共有パッケージは作らない。

|共通の課題|MyFinanceでの実装|Radarでの適用候補|
|---|---|---|
|出典と鮮度|source、asOf、更新時刻表示|一次資料URL、発表日、取得日、最終確認日を別々に保持|
|確定と推測の分離|速報／確定、estimated、未取得はnull|実証／商用を資料で確認し、AI抽出結果は未確認として保存|
|二重取込|安定ID、同一IDの変更は拒否|資料IDと案件IDを分離し、同じ発表の転載を重複案件にしない|
|分析の根拠|明細IDを伴うアラート|公募期限・採択額の根拠資料へ遷移|
|障害時の扱い|デモへ自動切替しない|収集失敗を新規案件ゼロと扱わず、前回成功時刻を表示|

## 分離するもの

- 金融明細、口座残高、認証情報、暗号化保存領域をRadarに送らない。
- 公開案件DBと個人金融DBは別の認可境界・ストレージにする。
- Radarの補助金・事業費を、本人の資産や収入として取り込まない。
- Radarから投資分析に引用する場合も「公開事業情報」に限定し、株価・実口座情報とは区別する。案件増加から売買推奨を自動生成しない。

## 実装が揃った後の順序

1. Radar側の実データ仕様とリポジトリを確認する。
2. 出典、取得時刻、最終成功時刻、エラー、再試行、安定IDの型と契約テストだけを共通化する。
3. 公開資料の引用を読み取り専用で接続し、両サービスの秘密情報が相互に流れないテストを追加する。

地図、100件の案件DB、自動収集、有料課金、公募通知はMyFinance側には実装していない。Radarの別作業と重複して新規リポジトリを作成しない。

## 現状

| データ経路 | 実装 | 鮮度・制約 |
|---|---|---|
| 共通CSV/JSON | ブラウザー内取込 | 手動取得時点。金融機関生CSVの全形式対応ではない |
| GAS v2 snapshot | サーバー間トークン認証POST | 画面表示中は60秒ごとに保存済みデータを再取得。銀行を60秒ごとに同期する意味ではない |
| 楽天カードのメール | 既存GASパーサー＋message ID重複防止 | GASの既存トリガーは1時間。速報・通常通知の照合が必要 |
| 銀行メール | 旧取込は残すが確定残高として表示しない | 通知漏れと初期残高の問題があり、FinanceAccountsの確認済み値を使う |
| 証券メール | SecuritiesInboxへ売買方向を保持して保存 | 全保有・移管・分割は通知だけで確定できない。FinanceHoldingsで照合 |
| 金融機関/集約事業者の公式API | 未実装 | 契約・同意・開発資格・認証スコープの確定後 |
| ローカルAI | Ollama HTTP経路実装 | モデル未配置のため実モデル生成は未検証 |

## 公式APIの接続候補

Moneytree LINKは銀行・カード・証券などの残高・取引情報を共通形式で提供するサービス。これは公式サービスの説明であり、本アプリで接続できたという意味ではない。

- [LINK API公式製品説明](https://getmoneytree.com/jp/link/link-api)
- [開発者向け導入窓口](https://getmoneytree.com/jp/link/contact): 見積もりに所定の手続きと秘密保持契約が必要と記載。料金は未確認。
- [API仕様書の申込窓口](https://getmoneytree.com/submission/request-api-documentation): 仕様書の閲覧に申込みが必要。未入手のAPIレスポンスを推測して実装しない。
- [公式iOS SDK](https://github.com/moneytree/moneytree-link-ios-sdk/blob/master/README.md): 開発/本番client ID、OAuthスコープ、PKCE、残高・投資データ読取・refresh権限の案内。

採用前に確認する項目は、対象金融機関、個人開発での契約可否、費用、取得頻度、提供元時刻、速報/確定のID対応、証券預り金と保有総額の区別。refresh要求の存在は瞬時の金融機関反映を保証しない。

## 将来のアダプターの境界

OAuth同意 → サーバーで認証コード交換 → 暗号化トークン保管 → 公式API取得 → v2の型と鮮度を検証 → スナップショット保存 → 差分通知。
PKCE/state、最小read-only scope、失効・再認証、指数バックオフ、レート制限を各提供者の仕様に従って実装する。
APIのURL・レスポンス形式を推測して実装しない。銀行のログイン情報を収集するスクレイピングやMFA回避は採用しない。

即時性は分離する：利用通知の到着時刻、加盟店の確定売上時刻、金融機関データ確認時刻、アプリ取得時刻。アプリ内のSSE/WebSocketだけ高速化しても金融機関の鮮度は改善しない。

## GAS移行手順

1. GASコードと既存シートをバックアップする。`Main.js`, `EmailParser.js`, `SpreadsheetWriter.js`, 新規`FinanceSnapshot.js`を反映。
2. Script Propertiesで `FINANCE_API_TOKEN` を設定。32文字以上のランダム値。Config.jsやGitに置かない。
3. 必要に応じてFinanceAccounts、FinanceHoldings、FinanceEntries、FinanceHistoryを作成。[データ仕様](DATA_CONTRACT.md)のヘッダーを使う。
4. 証券口座は現金残高だけをFinanceAccountsへ。保有総額を入れると二重計上になる。
5. 既存支出ログの8列目source_id、9列目replaces_idは新規メール書込時に拡張される。速報と通常通知の同一性を確認し、確定行のreplaces_idに速報のsource_idを入力する。
6. source_idがない旧明細は行番号IDで読む。並び替えを行う前にバックアップし、canonical entriesへの移行時は二重取込を避ける。旧版の誤重複排除で失われた行は元明細から照合する。
7. GASを新バージョンでデプロイ。旧公開デプロイを別途無効化し、匿名GETがデータを返さないことを確認する。
8. Next.jsの環境変数に接続URL、同一トークン、ユーザー名、20文字以上のパスワードを設定。ネットワーク越しはHTTPS。
9. 旧銀行ログは残るが確定残高には使わない。旧投信ログも自動変換しない。売買方向・口数単位が欠落した履歴を推測で再構成しない。

FinanceEntriesとメール由来ログの両方に同じ取引を重ねない。自動カテゴリ分類、複数明細メールの全形式解析、通知真正性の包括検証は今後の課題。

## AIとプライバシー

CSV/JSONはブラウザー内処理。端末保存はAES-256-GCM、ランダムsalt/nonce、PBKDF2-SHA256 600,000回。パスフレーズは保存・送信しない。自動保存ではない。端末を開いた状態での覗き見、悪意ある拡張機能、ブラウザー侵害には別対策が必要。

Ollama解説は明示的な同意と実行ボタンが必要。月・予算・支出など許可した集計数値だけを送信し、店舗名・口座ID・自由文をプロンプトへ挿入しない。接続先はサーバーの127.0.0.1固定。クラウドでアプリを動かす場合、ここでいう「ローカル」はそのサーバーであり、ユーザーのiPhoneではない。

生成結果は判断補助であり金額計算の正本ではない。LLMの応答がなくてもルール分析は動く。
